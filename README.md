# Azuero canopy height

Annual (2017–2025) gridded canopy height with per-pixel uncertainty for the Azuero
Peninsula, Panama, at 20–30 m. Spaceborne lidar samples (GEDI, ICESat-2 via SlideRule)
are labels. Wall-to-wall predictors map those labels across the peninsula, starting with
the AlphaEarth Foundations annual embeddings and adding terrain, Harmonized
Landsat-Sentinel, Sentinel-1 and airborne imaging spectroscopy (AVIRIS-3 / AVUELO)
where they help.

Accuracy is assessed with cross-validation that holds out several contiguous regions of
lidar data, and separately whole years. Two quantities are scored: absolute height, and
annual height change.

**Website:** <https://ashiklom.github.io/azuero-canopy-height/>. It has the methods,
results and an interactive map, and is served by GitHub Pages from `main:/docs`. To
enable Pages: Settings → Pages → Deploy from a branch → `main` / `/docs`.

## Results (version 1)

The final model is LightGBM on AlphaEarth embeddings, a time trend, terrain and
observation covariates. It runs on the native 20 m AlphaEarth grid, followed by a
robust per-pixel Kalman smoother. Accuracy is from spatial-region cross-validation (five
folds of contiguous held-out regions, with buffers):

| metric | value |
|---|---|
| height RMSE vs held-out GEDI | 5.5 m (R² 0.67, bias ≈ 0) |
| 90 % interval coverage (conformal, cross-fitted) | 90.0 % |
| year-to-year change in 2 km block means, r (map vs GEDI night power beams) | 0.61 |
| pixel-level 1-year change SD (empirical) | 6–9 m |

Whole-year hold-outs (leave-one-year-out, space × time) cost little accuracy.
The following did not improve held-out accuracy and are reported as ablations:
- context embeddings;
- HLS and Sentinel-1 predictors;
- AVIRIS-3 (AVUELO) spectroscopy;
- an MLP in place of LightGBM.

A monthly state-space model (version 2, `azuero.ssm`) is evaluated against version 1
on the website.

Web products are in `docs/data/cogs/`. For each year there is canopy height (20 m),
a calibrated SD (100 m) and annual change (100 m). Full-precision rasters are
regenerated with `azuero product v1_aef20`.

Stage tags are created by `scripts/tag_stages.sh`, because tag pushes were not possible
from the development environment.

## Layout

```
config.yaml        AOI, grids, years, CV and model settings, resource profiles
src/azuero/        library code (data loaders, labels, features, CV, models, SSM)
scripts/           stage drivers
results/           small committed outputs (metrics tables, figures, AOI)
docs/              static website + compact product COGs
data/              raw / intermediate data (gitignored; regenerated by the scripts)
```

## Setup

```bash
uv venv && uv pip install -e '.[dev]'
export EARTHDATA_LOGIN_USER=... EARTHDATA_LOGIN_PASSWORD=...
azuero aoi                  # build AOI polygon + grid masks
```

## Resource profiles

The method itself does not depend on any particular machine. The accommodations made
for a small VM (4 CPUs, 15 GB RAM, about 30 GB disk) are switchable. Each one is an
individual toggle under `resources` in `config.yaml`, and they are switched together by
`profile: small | full`:

| toggle | small | full |
|---|---|---|
| `delete_raw_after_composite` (stream HLS/S1/airborne data) | true | false |
| `alphaearth_read_level` (0 = native 10 m, 1 = 20 m overview) | 1 | 0 |
| `one_year_stack_on_disk` | true | false |
| `n_workers` / `max_mem_gb` | 4 / 12 | 32 / 128 |
| `max_train_rows` | 400k | all |
| `allow_gpu` / `run_large_models` | false | true |

There are three ways to select a profile or override a toggle:
- `azuero <step> --profile full`
- `AZUERO_PROFILE=full`
- per toggle, e.g. `AZUERO_RESOURCES__N_WORKERS=16`

The larger models in `azuero.models.registry` (spatial-context CNN, temporal transformer,
deep ensembles) are implemented but only run when `run_large_models` is enabled and the
hardware allows it.
